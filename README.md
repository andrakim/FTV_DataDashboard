# FTV Broadcast Analytics

Клиентская SPA для импорта ежедневных Excel-отчётов FTV, накопления истории и сравнения эфира. Реализованы база, парсер и математическое ядро по AGENTS.md и SPEC.md, а также пользовательский интерфейс для исследования программ и аудитории.

## Работа в интерфейсе

Основной экран — исходный график телесмотрения из длинной картинки Excel. Выберите даты, дни недели кнопками (например Пн–Пт), время 18:00–19:00 и программу. Приложение покажет фрагменты одинакового времени рядом, с исходной шкалой доли и подписями программ. Рамка выделяет выбранную программу; общий курсор помогает смотреть один момент во всех датах. Можно переключать недели, увеличивать картинку и открывать оригинал.

Четыре простых модуля: **Тенденция эфира**, **Программы**, **Сравнение периодов**, **Данные**. Постоянных боковых окон и конструктора графиков нет. Таблица программ использует тот же отбор дат и времени; подробности (вход/выход, зрители и конкуренты) открываются по нажатию. Сравнения недель, дней недели, сезонов и годов имеют собственные настройки и два фиксированных представления. CSV и резервная копия доступны в соответствующих модулях.

Картинка есть только за дату ежедневного отчёта. Недельная сетка и история за 60 дней не содержат исходных графиков за каждый день; отсутствующие даты показаны явно. Для пяти графиков нужны пять ежедневных отчётов.

Вертикальная ось 05:00–29:00 распознаётся по рамкам исходного PNG, геометрия проверена на 23 отчётах. Неизвестный формат показывается как полный оригинал без выдуманной привязки времени. Поминутных числовых рядов линии в этих файлах нет: показатели TOP и подписи под картинкой являются средними программ, а не числами выбранной минуты. Зрители из демографии переводятся из тысяч в человек, отсутствие не заполняется из доли. Картинки относятся к 18–54; для 25–34 доступны дневные показатели в сравнении периодов.

Схема IndexedDB и импортированные отчёты сохраняются. Импорт работает в Web Worker, исходные картинки декодируются последовательно только для видимых дат; геометрия кэшируется, Bitmap освобождается после отрисовки. Новые простые настройки хранятся отдельно от старых исследований. Подробная логика: [UI_SPEC.md](UI_SPEC.md).

## Запуск

Из корня проекта запустите `node scripts/serve.mjs` и откройте http://127.0.0.1:8080. Альтернативы: `python3 -m http.server 8080` либо `npx serve .`. Для загрузки библиотек CDN нужен интернет. Выберите один или несколько `.xlsx`-отчётов: данные сохраняются в IndexedDB текущего браузера и адреса сайта. Сервер только раздаёт статические файлы; отчёты обрабатываются в браузере.

## Контракты модулей

- `parseExcelFile(fileOrBuffer, { XLSX, JSZip })` возвращает `reportDateISO`, массивы `daily_metrics`, `grid_10min`, `program_logs`, `media_scans`, `warnings` и `metadata`. В браузере библиотеки берутся из глобальных CDN-импортов. `parseWorkbook(workbook)` позволяет отдельно тестировать нормализацию.
- `db.importReport(report)` атомарно сохраняет четыре хранилища и возвращает число добавленных/обновлённых записей. `get`, `getAll`, `loadData`, `deleteDate`, `clear`, `close` предоставляют чтение и управление БД. Пустые значения не стирают заполненные; источники с точными данными имеют приоритет над недельными сетками. Для одинаковых источников более свежий отчёт имеет приоритет. Порядок перекрывающихся импортов не меняет результат.
- `state.getState()`, `state.setState(patch)`, `state.subscribe(callback)` и `state.reset()` управляют валидируемым неизменяемым состоянием. `subscribe` возвращает функцию отписки.
- `compareWeeks(data, {isoWeekYear, isoWeek}, baseline, options)`, `analyzeDayOfWeek(data, options)`, `compareSeasons(data, {season, seasonYear}, baseline, options)`, `compareYears(data, year, baselineYear, options)` — чистые функции. Универсальная точка входа: `comparePeriods(data, {mode, periodA, periodB, ...options})`.
- `detectSlotDrops(data, options)` возвращает провалы с триггерами, удержанием входа/выхода, бенчмарком тайм-блока, приростом конкурентов и демографическими потерями. `includeHealthy: true` добавляет программы без срабатываний.
- `analyzeRecurrence(data, options)` возвращает календарные `observations`, отдельные `groups` по точным программам/сетке и парные наблюдения `competitors`. Параметры: `mode: 'program' | 'slot'`, точное `title` (без учёта регистра и лишних пробелов), `channel`, `dayOfWeek`, `startSec`, `endSec`, общие фильтры, `includeApproximate`, `signal: 'leadIn' | 'baseline'`, `retentionThreshold`, `baselineDropPercent`.
- `measureWindow(rows, startSec, endSec, metric)` взвешивает значения по непересекающимся интервалам и возвращает покрытие и конфликтующие секунды. Дубликат не увеличивает вес, конфликт исключается из измерения. Аналитические функции не меняют входные данные.
- `createAiringIndex(catalog, data)`, `filterAirings(catalog, options)`, `describeAiring(index, program, {competitors})`, `airingCalendarDays(index, rows, options)` и `summarizeSelectedAirings(contexts, {groupBy})` — чистые функции просмотра и пользовательского сравнения. Конкуренты показываются независимо от роста или наличия предыдущего слота. Для оценки доли окна нужно ≥90% покрытия без конфликтов; известные названия в неполном окне остаются видимыми. TOP имеет приоритет при достаточном покрытии, иначе используется сетка с указанием источника.

`data` — объект с массивами `daily_metrics`, `grid_10min`, `program_logs`, получаемый из `db.loadData()`. Общие фильтры: `audience: '18-54' | '25-34'`, `from`, `to`, `excludeNonWorkdays`. Для сравнения дополнительно доступны `year`, `month`, `season`, `seasonYear`, `isoWeekYear`, `isoWeek`, `dayOfWeek`.

## Правила расчётов

- Все даты вычисляются по UTC без зависимости от часового пояса устройства. Часы 00:00–04:59 приводятся к 24:00–28:59, значения 24:xx–28:xx сохраняются. Интервалы полуоткрытые: `[startSec, endSec)`.
- Зима с `seasonYear: 2026` охватывает декабрь 2025 — февраль 2026. `year: 2026` вместе с `season: 'winter'` выбирает зимние месяцы внутри календарного 2026 года. ISO-недели обязательно задаются с ISO-годом. Годовые/месячные показатели используют календарный год; недельное выравнивание — ISO-год, включая пограничные дни соседнего календарного года.
- Дневные метрики усредняются по доступным дням; отсутствующие значения исключаются, измеренные нули сохраняются. Средние по слотам — по наблюдаемым датам, метрики тайм-блоков — по длительности покрытия. В результатах есть количество наблюдений. Это средние опубликованных долей, а не повторный расчёт доли по телевизионной аудитории.
- Сетка и TOP в предоставленных отчётах относятся к 18–54. Для 25–34 доступны дневная история и региональные метрики; послотовые значения остаются `null`. Демография выражена в тысячах зрителей.
- Средний дневной охват не позволяет определить уникальный накопленный охват: `cumulativeUniqueReach` остаётся `null`. `sumDailyReachPercent` — сумма дневных охватов с повторными зрителями, а не уникальная аудитория.
- Триггеры: удержание ≤70% при входной доле ≥1%; доля <65% дневной в 18:00–23:00 при стабильном/растущем рейтинге; доля строго ниже обеих соседних программ. Соседи должны относиться к одному эфирному дню, без перекрытия и с паузой не более `maxGapSec` (по умолчанию 600 секунд).
- Конкуренты сравниваются с полным десятиминутным слотом перед слотом начала провала. Показатель за окно программы взвешивается по секундам пересечения. Используются точные TOP-логи, если покрыто ≥90% обоих окон; иначе проверяется сетка с тем же минимальным покрытием. Конфликтующие перекрытия не допускаются. Возвращаются доли покрытия и названия передач из выбранного источника. Положительная разница указывает на одновременный рост конкурента, но не доказывает переход конкретных зрителей.
- Все 22 листа перечислены в `metadata.sheetInventory`, видимость не ограничивает парсинг. Листы с контрактом нормализуются; прочие листы сохраняются в `daily_metrics.additionalSheets` как ячейки после распаковки объединений. Для облегчённого импорта это можно отключить через `preserveAdditionalSheets: false`.

`pnpm install --store-dir .pnpm-store --node-linker=hoisted`, затем `pnpm test` (или `node --test tests/*.test.js`). Тестовые зависимости используются только для проверки: SPA не требует установки npm-пакетов. Проверки охватывают реальные файлы из `samples/`, ошибочное имя `11.11.26` с датой 11.10.2026 внутри книги, перекрывающиеся импорты, откат транзакций, границы ISO-года, все режимы сравнения, условия триггеров и известную потерю аудитории Fresh news за 06.10.2026.

`pnpm check` проверяет синтаксис JS, локальные импорты, уникальность HTML id и наличие ресурсов. `pnpm audit:data` независимо сверяет нормализованные значения с оригинальными ячейками 23 локальных отчётов, включая прямое чтение якорей объединённых ячеек, и проверяет одинаковый результат прямого/обратного порядка загрузки. Результат записывается в игнорируемый `test-results/data-audit.json`. Можно передать другую папку: `node scripts/audit-data.mjs <путь>`. Это контроль предоставленного формата отчётов, а не универсальный Excel-валидатор.

Браузерная регрессия: сначала `pnpm build`, затем `pnpm test:browser`. Нужны Chrome, локальный пример за 06.10.26 и доступный пакет Playwright. Для внешней установки задайте `PLAYWRIGHT_MODULE` как абсолютный путь к пакету; `BROWSER_CHANNEL` меняет канал браузера (по умолчанию `chrome`). Скрипт создаёт отдельный профиль, проверяет реальный импорт Worker, пять исходных графиков Пн–Пт 18:00–19:00, соответствие исходным пикселям, программу и общий курсор, детали/оригинал, каналы и пропуски, четыре режима периодов, CSV/резервную копию, мобильный экран и сохранение настроек. Данные и скриншоты проверки не входят в сборку.

## Повторяемость: метод и границы выводов

Одна дата даёт не больше одного наблюдения. В режиме программы выбирается полный выпуск с началом в заданном полуоткрытом окне. Несколько подходящих выпусков требуют сужения окна. В режиме времени оценивается среднее по пересекающим окно программам, с весом по секундам перекрытия. Точные TOP-границы не означают посекундные измерения аудитории. Десятиминутная сетка повторяет средние показатели программ; это не независимая поминутная телеметрия.

Точные программы и приблизительная сетка имеют отдельные эталоны и частоты. Для частично заполненного TOP-дня каталог сохраняет программы из неперекрывающихся участков сетки; точные записи имеют приоритет. По умолчанию приблизительные выпуски исключены из анализа закономерностей. Неизвестный тип дня исключается при фильтре «Только рабочие дни» и объясняется отдельно.

Эталон каждого наблюдения — медиана других дат с тем же источником (текущая дата исключена). При минимум четырёх других датах необычно низким считается значение ниже медианы больше чем на `max(0.25 п.п., baselineDropPercent% × медиана, 3 × 1.4826 × MAD)`. Порог защищён от нулевого MAD и шума округления. Это описательное сравнение всего периода, включая будущие относительно выбранного выпуска даты; оно не является прогнозом.

Для выбранного сигнала нужны минимум пять вычислимых дат. Частота ≥60% помечается как повторяющийся провал; редкие сигналы ≤25% при необычно низкой доле — как возможная разовая аномалия; остальные — нерегулярные. Отсутствие входа, данных, неоднозначные выпуски и конфликты не считаются здоровыми днями. Правила операционные, без заявления статистической значимости. Отдельная таблица конкурентов показывает рост в дни провала и среднее изменение в дни без провала; знаменатель включает и положительные, и нулевые, и отрицательные изменения при наличии обоих окон.

Аудит 14.10.2026: 23 файла, 110 489 контролей, 89 дней, 5 328 слотов, 22 807 точных записей программ. Значения совпали с исходными ячейками; порядок импорта не изменил результат. В окне начала Fresh news (уз) 18:00–20:00 доступны три точных четверга, у двух падение на входе; этого недостаточно для вывода о систематичности.

## Следующие улучшения для исследования закономерностей

1. Сравнение одной программы при разных предшественниках и после переноса времени: помогает отделить содержание от качества входа.
2. Календарь премьер, повторов, праздников, рекламных пауз и внешних событий; ручное исключение дат с сохранённой причиной.
3. Тепловая карта «день недели × время» с числом наблюдений и частотой сигналов, чтобы искать проблемные зоны без заранее выбранной программы.
4. Сохранённые гипотезы и сравнение периода до/после изменения сетки на сопоставимых днях.
5. Импорт настоящих поминутных измерений и отдельных программных данных 25–34 для анализа внутри выпуска и возрастных различий.




## Улучшения интерфейса и точности — 16.10.2026

- Единая верхняя навигация, компактные фильтры и читаемая сводка доступности. На телефоне фильтры можно свернуть, сохранив краткое описание выборки.
- Быстрые периоды: последние семь дней относительно последнего исходного графика и все загруженные даты, включая числовую историю. Переключатель «Только даты с графиком» скрывает пустые колонки, а число отсутствующих графиков остаётся видимым. Сброс возвращает последнюю неделю.
- Поиск по части названия в таблице программ, сортировка доли по возрастанию/убыванию и отбор точного TOP или сетки. CSV экспортирует текущую выборку целиком, включая строки за пределами страницы. Измеренные нули сохраняются; отсутствующая доля идёт в конец сортировки.
- «Все четверги» и аналогичные действия открывают доступный период расписания выбранного канала. Незавершённый ввод времени сохраняется при смене масштаба или вкладки. Обычные ночные часы 00:00–04:59 принимаются как 24:00–28:59.
- Сравнение периодов показывает разницу A−B и позволяет менять периоды местами. Доли, рейтинг и охват сравниваются в процентных пунктах, время просмотра — в минутах. Недели, сезоны и годы используют все дни своего периода; фильтр дня недели действует только в соответствующем режиме.
- Восстановление резервной копии доступно в пустой базе. Результат импорта показывает предупреждения/ошибки и позволяет открыть загруженные даты.
- Метрики конкурентов хранятся отдельно по аудиториям. Сводки программ также разделяют аудитории и точные/приблизительные источники. Старые записи и резервные копии поддерживаются.

Для полного прогона тестов на внешнем каталоге примеров задайте `FTV_SAMPLE_DIR`; иначе используется локальный `samples/`. Например в PowerShell: `$env:FTV_SAMPLE_DIR='C:/path/to/reports'`, затем `node --test tests/*.test.js`.
